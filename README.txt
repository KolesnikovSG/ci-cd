Пайплайн автоматизирует процесс сборки, тестирования и деплоя приложения Todo (backend и frontend). Основные этапы работы:

Build — сборка backend приложения с установкой зависимостей и сбором статических файлов.

Test — запуск тестов backend с использованием базы данных PostgreSQL.

Deploy — развертывание приложения на staging и production  окружениях.

Этапы пайплайна
1. Build Backend (build_backend)
Устанавливаются необходимые пакеты (python3-pip, python3-venv).

Обновляется pip.

Переход в директорию backend.

Установка зависимостей из requirements.txt, а также дополнительных пакетов для тестирования.

Выполняется сбор статических файлов Django.

Результаты работы сохраняются как артефакты на 1 неделю.

2. Test (test_backend)

Запускает сервис postgres 14 для тестовой базы.

Создается виртуальное окружение.

Устанавливаются зависимости.

Выполняются тесты с помощью pytest.

Генерируется отчет в формате JUnit.

Артефакты тестового отчета сохраняются для анализа.

3. Deploy Staging (deploy_staging)
Запускается по ветке br1 после успешного тестирования.

Поднимает SSH агент и настраивает ключи для доступа к серверу.

Использует rsync для копирования backend и frontend в директорию staging.

На сервере активируется виртуальное окружение, устанавливаются зависимости.

Переключается конфигурация nginx на staging.

Запускается сервис staging (systemd).

4. Deploy Production (deploy_production)

Запускается вручную (manual) по ветке br1.

Аналогично staging, но деплой происходит в production директорию.

Останавливается staging сервис.

Запускается сервис production.

Переменные окружения
PROJECT_DIR, BACKEND_DIR, FRONTEND_DIR — директории проекта.

PYTHON_VERSION — используемая версия Python.

PIP_CACHE_DIR — кэш для pip.

PRODUCTION_DIR, STAGING_DIR — директории на сервере для развертывания.

DEPLOY_HOST — IP сервера для деплоя.

DEPLOY_USER — пользователь SSH для подключения к серверу.

DEPLOY_KEY — приватный SSH ключ, настроенный в CI/CD настройках.


Как пользоваться
Коммит в ветку br1 запускает сборку, тестирование и деплой в staging.

Для деплоя в production вручную запускать deploy_production в GitLab UI.
